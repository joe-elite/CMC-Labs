ANSWERS TO LAB QUESTIONS
=========================

Q: What is the role of the Deployment?
A: The Deployment expresses the desired state of the application.
   It tells Kubernetes to always keep 3 replicas of the pod
   running using the lab3-multi image. The Deployment controller
   continuously watches the actual state and reconciles it to
   match the desired state. If a pod dies, the controller
   creates a new one automatically.

Q: What is the role of the Service?
A: The Service provides a stable network endpoint for accessing
   the pods. Pods have dynamic IP addresses that change when
   they restart. The Service has a fixed ClusterIP and routes
   traffic to all healthy pods using label selectors.
   This decouples clients from the specific pod IPs.

Q: Why did we not manually choose a node for each replica?
A: Kubernetes scheduling is declarative. We describe WHAT we
   want (3 replicas of this image) not WHERE to run it.
   The scheduler automatically picks the best node based on
   available resources, constraints, and policies. This makes
   deployments portable and resilient because the application
   is not tied to specific machine names or IP addresses.

KEY TAKEAWAY
============

Kubernetes orchestration removes the need to manually manage
individual containers on specific machines. The Deployment
controller ensures the desired number of replicas are always
running. The Service ensures traffic reaches healthy pods
regardless of where they are scheduled or what IP they have.
This is the foundation of cloud-native application deployment.
