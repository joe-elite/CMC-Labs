ANSWERS TO LAB QUESTIONS
=========================

Q: Why does the container think its main process is PID 1
   while the host sees a different PID?
A: Linux PID namespaces give each container its own isolated
   process ID space starting from 1. The container only sees
   processes inside its own namespace. The host sees ALL
   processes across all namespaces with their real global PIDs.
   This is why bash appears as PID 1 inside the container
   but as PID 22342 on the host - same process, two different
   namespace views.

Q: How do cgroups complement namespaces?
A: Namespaces and cgroups solve different problems together.
   Namespaces isolate VISIBILITY - a container cannot see
   processes, files, or network interfaces outside its namespace.
   Cgroups isolate RESOURCES - a container cannot consume more
   CPU, memory, or I/O than its configured limits allow.
   Without namespaces, containers would see each other's processes.
   Without cgroups, one container could starve all others of CPU
   or memory. A container runtime combines both mechanisms to
   produce a fully isolated and fairly scheduled execution unit.

KEY TAKEAWAY
============

Containers are not virtual machines. They are ordinary Linux
processes running with two kernel features applied:
- Namespaces: control what the process can see
- Cgroups: control how much the process can use
This is why containers start in milliseconds compared to VMs
which need to boot an entire operating system.
